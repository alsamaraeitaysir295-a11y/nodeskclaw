## 0. 前置任务：存量漏洞修复（独立于 Phase 1，优先执行）

**`POST /{agent_id}/chat` 缺会话归属校验（IDOR，已核实）**：`session_id` 直接取自请求体（`app/api/external_agents.py:337` 附近），`get_messages(session_id)` 只按 session_id 过滤、不校验 user_id/org_id（`external_agent_chat_service.py:63`）。知道他人 session UUID 的用户可读取他人对话上下文、并向他人会话写入消息。同文件 `GET /sessions/{id}/messages` 走 `get_session(session_id, user_id)` 有校验，证明 chat 端点属遗漏。

**修法**：chat 端点在取 session 后先 `get_session(session_id=..., user_id=current_user.id)` 校验归属，不存在或非本人则 403（会话不存在与无权同响应，避免探测）。附带修两个次要项：
- 前端 4 条外部 Agent 路由（`router/index.ts:161-185`）补 `requiredOrgRole` meta，与兄弟路由对齐；
- `services/externalAgents.ts:53` protocol 类型联合补 `nap`（新增 `rag_standard` 时一并处理）。

## 1. 背景与现状（已对齐代码）

平台已有外部 Agent 模块（v1），代码位置：

| 文件 | 内容 |
|---|---|
| `nodeskclaw-backend/app/api/external_agents.py` | REST 路由：CRUD、`/sync`、`/attachments/upload`、`/sessions`、`/chat`(SSE) |
| `nodeskclaw-backend/app/schemas/external_agent.py` | Pydantic Schema |
| `nodeskclaw-backend/app/services/external_agent_adapter.py` | 协议适配：`openai_compatible`、`custom`、`nap`（SSE 解析、连通性校验） |
| `nodeskclaw-backend/app/services/external_agent_chat_service.py` | 会话/消息持久化 |
| `nodeskclaw-backend/app/services/external_agent_service.py` | CRUD；**api_key 已 AES-256-GCM 加密存储**（`api_key_encrypted` + `app/core/security.py` 的 `encrypt_sensitive`） |

v1 已具备：endpoint + api_key 登记（密钥已加密）、健康检查（is_reachable/last_checked_at）、SSE 聊天、附件上传、会话隔离（除 §0 所述 chat 端点遗漏）。

**v1 的缺口（本方案要解决的）：**

1. 协议枚举没有"自定义 REST 问答服务"（如内网 RAG：`/api/v1/agent/stream|query|sessions|history`）。
2. 不支持 B类"信息化系统型"插件：无入参 schema、无表单化调用入口。
3. 没有"插件清单(Manifest)一次提交、平台自动校验+初始化"的流程。
4. SSRF 零防护（全后端无私网/回环校验；且 `_resolve_wsl_endpoint` 会把 localhost 重写为宿主机 IP，与防护方向相反）；HTTP 通用限流基建不存在（仅登录失败限流与消息总线限流，均为进程内字典，多副本失效）。

## 2. Phase 1 目标与范围

**目标一句话：管理员提交一份插件清单（JSON），平台自动校验连通性、注册插件；用户端自动出现对应能力入口——A类（对话型）进入聊天界面，B类（工具型）渲染动态表单（含文件上传），提交后返回结构化结果。**

Phase 1 范围内（IN）：

- Manifest 定义 + 管理端提交向导（3 步：基本信息 → 接口定义 → 试调确认）
- 新增协议适配器 `rag_standard`（对接内网 RAG 服务的标准问答协议）
- 新增插件类型 `tool`（B类）：input_schema 驱动后端校验 + 前端动态表单渲染
- 表单直连调用：用户提交表单 → 平台后端代理调用外部接口 → 结果以 JSON 卡片/表格展示
- 文件上传中转（默认 multipart 转发，见 §8）
- SSRF 防护（新建能力）+ 每插件限流（新建能力，见 §9.5）+ 健康检查与启停
- i18n 合规（zh-CN/en-US，CLAUDE.md 强制要求；现存 3 个 External Agent 视图零 i18n 属存量债务，**新增代码必须合规**）

Phase 1 范围外（OUT）：

- OpenAPI/Swagger 导入、LLM 辅助生成 Manifest（Phase 2）
- 主 Agent 意图识别自动路由、function-calling 编排（Phase 1.5/2，见附录 B）
- OAuth 鉴权、MCP 插件直连（Phase 3）
- 插件市场/跨组织共享（远期）
- 存量视图的 i18n 补齐（另行安排，不阻塞本 Phase）

**需产品决策（实施前确认）**：`features.yaml` 无 external_agent 条目，当前属 CE。企业集成能力是否加 `FeatureGate` 门控归 EE？本方案默认保持 CE，待决策。

## 3. 核心抽象：插件分类

| type | 名称 | 特征 | 用户入口 |
|---|---|---|---|
| `chat` | A类·对话型 | 有 SSE/同步问答接口，可能自带会话 | 聊天界面（复用 v1 会话 UI） |
| `tool` | B类·信息化系统型 | 纯 REST，无会话，结构化出入参 | 动态表单 → 结果卡片 |

## 4. Plugin Manifest 完整定义

管理员最终提交的 JSON（后端同时提供等价的分步表单，前端向导收集后组装成此结构）：

```json
{
  "name": "热压缺陷知识问答",
  "description": "基于工艺文档的 RAG 问答。此描述同时作为 AI 选择工具的依据，请说明适用场景。",
  "icon_emoji": "flame",
  "theme_color": "#E24B4A",
  "type": "chat",

  // ── chat 型 ─────────────────────────────
  "protocol": "rag_standard",
  "endpoint": "http://10.50.54.233:4080",
  "api_key": null,
  "session_managed_by": "external",

  // ── tool 型 ─────────────────────────────
  "invoke": {
    "endpoint": "http://10.50.54.233:9000/api/v1/defects/query",
    "method": "POST",
    "auth": { "type": "api_key_header", "header_name": "X-API-Key", "token": "加密后存储" },
    "timeout_seconds": 30,
    "pass_mode": "multipart"
  },
  "input_schema": {
    "order": ["line", "date_range", "file"],
    "fields": {
      "line":    { "type": "string",  "ui": "select", "label": "产线", "required": true,
                   "options": ["热压1线", "热压2线"] },
      "date_range": { "type": "object", "ui": "daterange", "label": "日期区间", "required": false },
      "file":    { "type": "file",    "ui": "upload", "label": "明细文件",
                   "accept": [".xlsx", ".csv"], "max_mb": 20, "required": false }
    }
  },
  "output_hint": { "display": "table", "items_path": "data", "primary_key": "defect_code" }
}
```

**字段规范（后端校验规则）：**

- `type`：必填，枚举。
- chat 型：`protocol` + `endpoint` 必填；`session_managed_by` 仅 `rag_standard` 允许 `external`。
- tool 型：`invoke.endpoint` 必须 http(s)；`method` 限 `GET|POST|PUT|PATCH|DELETE`；`auth.type` 限 `none|bearer|api_key_header`，其中 `api_key_header` **必须**带 `header_name`；`timeout_seconds` ≤ 120；`pass_mode` 限 `multipart|url_ref`，**默认 `multipart`**。
- `input_schema.fields[*].type`：`string|number|boolean|object|file`；`ui`：`input|textarea|select|number|switch|date|daterange|upload`；`options` 仅 select 必填；`max_mb` ≤ 50。
- `daterange` 序列化格式**定死**为 `{"start": "ISO-8601", "end": "ISO-8601"}`，前端控件、后端校验、外部传参三处一致。
- `output_hint.items_path`：点号路径（如 `"data"`、`"result.items"`），前端按此定位表格数据数组；`display` 限 `table|json`。
- `input_schema` 存 JSON 列；运行时校验**统一用 pydantic 动态构建**（`create_model`），**不引入 jsonschema 依赖**（`pyproject.toml` 现无此依赖）。
- `icon_emoji`：数据字段（用户配置值），CLAUDE.md 禁 emoji 规范针对代码/文案，此处作为用户数据豁免；前端图标优先 `lucide-vue-next`，emoji 仅兜底展示。

## 6. 后端 API 设计

在现有 router（`/api/v1/external-agents` 前缀，实施时以 `app/api/router.py` 实际注册路径为准）上扩展：

### 6.1 管理端

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/plugins/validate` | **只校验不落库**：Manifest 合法性 + 连通性试调，返回逐项结果。向导第 3 步调用 |
| POST | `` （现有） | 创建插件，扩展接收新字段；落库前强制先通过 validate 的规则 |
| PATCH | `/{id}` （现有） | 更新；`input_schema`/`invoke_config` 变更时 version+1 并触发重新试调 |
| POST | `/{id}/probe` | 手动健康探测，更新 is_reachable + last_probe |

权限：创建/更新/校验用现有 `require_org_member_role("operator")`（**注意不是 `require_org_operator`，且勿与校验 AdminMembership 的 `require_org_role` 混用**，见 `app/core/deps.py:246/343`）。

`POST /plugins/validate` 响应示例：

```json
{ "success": true,
  "data": {
    "schema_ok": true,
    "connectivity": { "ok": false, "http_code": 502, "latency_ms": 8,
                      "error": "upstream unavailable" },
    "warnings": ["外部服务当前不可达，可保存为 draft 但无法启用"]
  } }
```

**连通性试调规则**：chat 型按 protocol 调探活路径（`rag_standard` → `GET {endpoint}/api/v1/agent/sessions?limit=1`）；tool 型以空参或最小合法参数调一次 invoke.endpoint（GET 直接调，POST 发仅含必填默认值的 body；必填项无默认值则跳过实际调用、仅 DNS/TCP 级校验并给 warning）。

### 6.2 用户端（tool 型核心新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/{id}/form` | 返回该插件的 input_schema（仅 status=active 且用户有权限时） |
| POST | `/{id}/invoke` | **表单直连调用**。multipart 或 JSON |
| POST | `/{id}/files` | 表单文件上传中转，返回 file_id；invoke 时以 file_id 引用 |

`POST /{id}/invoke` 处理流程：

1. 权限检查 + 插件 status=active + is_reachable 检查（不可达返回 **503** 带友好错误信息，不透传外部状态码）。
2. 按 input_schema 用 pydantic 动态模型校验参数（缺必填/类型不符 → 422 带字段级错误信息，错误文案走 i18n message_key）。
3. 组装外部请求：普通字段进 JSON body（GET 进 query）；file 字段按 `pass_mode` 处理（§8）。
4. 后端代理调用（httpx，timeout=invoke.timeout_seconds），注入 auth。
5. 响应处理：2xx → 按 output_hint 组装 `{success:true, data, display, items_path}`；非 2xx → `{success:false, upstream_status, error}`。**外部返回内容一律作为数据透传，前端按 JSON 渲染，绝不作为 HTML 插入。**
6. 写调用审计日志（谁、哪个插件、参数摘要、耗时、结果状态），接入现有 audit 模块。

### 6.3 chat 型新增协议：`rag_standard`

适配器（`external_agent_adapter.py`）新增分支，协议契约见附录 A。要点：

- `chat_stream`：POST `{endpoint}/api/v1/agent/stream`，body `{question, session_id, mode:"auto"}`；解析 SSE：累积 answer 增量、`{"type":"done"}` 收尾、`{"type":"error"}` 抛错转平台统一错误事件。
- `session_managed_by="external"` 时：平台会话 ↔ 外部 session_id 映射（§5 新列）；创建平台会话时同步调外部 `POST /api/v1/agent/sessions`；删除会话历史时透传外部 `DELETE /api/v1/agent/history/{sid}`。
- 健康检查：`GET {endpoint}/api/v1/agent/sessions?limit=1` 返回 200 即 reachable。

## 7. 前端设计（nodeskclaw-portal）

### 7.1 管理端：插件提交向导（新页面）

技术栈：Vue3 + 手写共享组件（`src/components/shared/`）+ Tailwind v4 + `lucide-vue-next` 图标。**`reka-ui` 在 package.json 中但 src/ 零引用（孤儿依赖），勿使用。**

三步向导：

1. **基本信息**：名称、描述（提示"此描述是 AI 选择工具的依据"）、图标、主题色、类型选择（chat / tool 卡片）。
2. **接口定义**：
   - chat 型：协议下拉（openai_compatible / nap / rag_standard / custom）、endpoint、api_key（密码框）、会话归属说明。
   - tool 型：endpoint、method、鉴权（类型 + header 名 + 密钥）、超时、pass_mode；**参数构建器**——逐行添加字段（字段名、类型、UI 控件、label、必填、options），右侧实时预览表单效果。
3. **试调确认**：调 `/plugins/validate`，逐项展示 ✅/⚠️/❌；不可达时允许"保存为草稿"。

### 7.2 用户端：能力入口 + 动态表单

- 插件列表页（复用/扩展现有外部 Agent 列表）：chat 型点击进聊天（v1 已有），tool 型点击进表单页。
- **动态表单组件 `PluginForm.vue`**：**实现参考现成先例 `src/views/InstanceChannels.vue:399-468`**（已实现 schema 驱动渲染：字段类型分发、default 填充、无 schema 降级 JSON 编辑器），按该模式抽取：

| ui 值 | 控件 | 数据类型 |
|---|---|---|
| input / textarea / number | 基础输入 | string / number |
| select | 下拉 | string（options） |
| switch | 开关 | boolean |
| date | 日期 | string(ISO) |
| daterange | 日期区间 | `{"start": ISO, "end": ISO}` |
| upload | 文件上传 | 调 `/{id}/files` 拿 file_id，展示进度与文件名 |

- 按 `order` 排序；必填星号；提交调 `/{id}/invoke`，loading 态 + 字段级错误回显。
- **结果渲染 `PluginResult.vue`**：按 `items_path` 定位数组渲染表格（注意：平台**无通用表格组件**，AuditLogTable 硬绑定接口不可复用，需新写轻量表格渲染）；非数组/嵌套深的数据渲染 JSON 树卡片；提供"复制 JSON"。

- 全部新文案走 i18n（`useI18n`，zh-CN/en-US 双语键），字段级 422 错误映射到表单字段提示。
- 现存聊天页 `ExternalAgentChat.vue` 为手写转义、无 markdown 渲染；**新增代码统一走 `src/utils/markdown.ts` 的 `renderMarkdown()`（内含 DOMPurify）**，并作为独立改进项为聊天页接入。

## 8. 文件上传中转

- 用户文件 **只传平台**（`/{id}/files`），前端永不直连外部系统。
- 平台落对象存储（复用 storage_service）拿 storage_key + file_id（TTL 24h）。注意存储后端差异：本地后端为 HMAC 签名 URL（`storage_service.py:123`），S3 后端为 presigned URL（`:92`），TTL 默认 3600s。
- invoke 时按 `pass_mode`：**默认 `multipart`** —— 平台流式转发文件本体（外部接口无需回取，最简可靠）；`url_ref` —— 平台生成临时下载 URL（按上述存储后端差异生成）放入 body，由外部系统回取。
- 大小/类型白名单在 `/{id}/files` 就拦截，不要等到 invoke。

## 9. 安全要求（实施时为验收项）

1. **密钥**：沿用 v1 AES-256-GCM 加密（`encrypt_sensitive`），响应体永不回传明文（返回 `***last4`）。
2. **SSRF（新建能力，当前零防护）**：威胁模型是**管理员提交的 URL**（普通用户请求本就全程由后端代理发起）。防护点：提交/更新时校验目标地址；org 级"允许的目标网段"配置，默认放行私网（外部系统多在内网 10.x）、**硬禁云元数据地址 `169.254.169.254`**。⚠️ 必须处理与 `_resolve_wsl_endpoint`（`external_agent_adapter.py:62`，把 localhost 重写为宿主机 IP）的冲突：该重写仅在 `DEBUG=true` 时启用。
3. **XSS**：外部返回只做数据渲染（§6.2 第 5 步）；聊天/结果展示统一走 `renderMarkdown()`（DOMPurify），禁 v-html 裸插。
4. **权限**：创建/更新需 `require_org_member_role("operator")` 及以上；invoke 需登录 org 成员；**所有会话级端点强制归属校验**（存量 chat 端点缺陷见 §0，先行修复）。
5. **限流（新建能力，现无 HTTP 通用限流基建）**：每插件每用户默认 10 次/分钟，超限 429。单副本用进程内令牌桶（参考 `auth_rate_limit.py` 模式）；**多副本部署需另行决策**（DB 计数或引入 Redis），作为独立任务估算，不塞进 invoke 链路工时。
6. **审计**：invoke 全量记录（audit 模块已有基建，接入即可）。

## 10. 健康检查与生命周期

- 后台定时任务（复用现有 sync/health 机制）：chat 型按协议探活；tool 型轻探（HEAD/OPTIONS 或 DNS 解析），频率 60s，连续 3 次失败标记不可达并在前端置灰。**判定规则：HTTP 405/404 视为"可达"**（大量 REST 接口对 HEAD/OPTIONS 返回 405，属可达而非故障），仅连接层错误（DNS 失败/拒绝/超时）判不可达。
- 状态机：`draft → active ⇄ disabled`；不可达不自动停用，仅置灰提示 + 管理员可手动停用。
- Manifest 变更（input_schema/invoke_config）：version+1，前端表单按版本缓存失效。

## 附录 A：rag_standard 协议契约（首个对接对象：内网 RAG 服务）

Base：`http://10.50.54.233:4080`（2026-08-19 实测全部 502，服务待重启；**Phase 1 验收用 mock 替身**，真实服务恢复后按此附录复测并回填真实报文）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/v1/agent/stream` | `{question, session_id, mode:"auto"}` | `text/event-stream`；逐量推送；结束 `data: {"type":"done","answer":"...","cancelled":false}`；错误 `data: {"type":"error","error":"..."}` |
| POST | `/api/v1/agent/query` | 同上 | `{success, question, session_id, answer, cancelled}` |
| GET | `/api/v1/agent/sessions?limit=20` | — | `[{session_id, title, turn_count, last_active}]` |
| POST | `/api/v1/agent/sessions` | `{session_id, title}` | 创建会话 |
| GET | `/api/v1/agent/history/{sid}?limit=10` | — | `{session_id, history:[...], turn_count}` |
| DELETE | `/api/v1/agent/history/{sid}` | — | `{message}` |

适配要点：done 事件里的完整 answer 用于持久化兜底；增量事件格式需服务恢复后抓包确认（若增量也是 `{"type":"delta","text":...}` 之类，解析器按此扩展）。

**多轮对话与会话隔离规则（强制，验收项）：**

1. **外部 session_id 由平台生成**，格式如 `plat_{平台会话id}`，全局唯一；**严禁**使用外部文档示例中的默认值（如 `default`）——否则所有用户共享同一外部上下文，造成跨用户数据串扰。
2. 每个平台会话（已含 user_id/org_id/agent_id）映射且仅映射一个外部 session_id；不同用户、不同会话的外部 id 必然不同，多轮上下文由外部 RAG 按各自 session_id 隔离维护。
3. **会话归属校验**：`GET history` / `POST chat` / `DELETE history` 等所有会话级端点，必须先校验目标会话属于当前登录用户，否则 403（含 §0 存量缺陷修复）。
4. **外部会话失效降级**：外部返回"会话不存在"类错误时，适配器自动新建外部会话、更新映射、重放当前问题；用户仅感知上文记忆重置，不报错中断。
5. 每轮问答同步持久化到平台消息表（复用 v1 `_persist_messages`）：外部历史被清/被截断时，用户端聊天记录仍完整展示。
6. Phase 1 插件级鉴权（api_key）为管理员密钥、全体用户共用，**不向外部传递平台用户身份**；若外部系统需要按用户记账/隔离数据，Phase 2 增加 `identity_header` 透传选项。

## 附录 B：Phase 1.5 / 2 / 3 预留

**Phase 1.5（从 Phase 2 提前，视优先级）——tool 插件接入 AI 员工函数调用**：
- 将 tool 插件的 `input_schema` 自动转换为 function-calling 工具定义（name/description/parameters），注册进平台 skills/genes 体系，AI 员工意图识别后直接调用，用户无需手动填表单。
- 调用链路与 `/invoke` 复用同一 service（校验、鉴权、审计、限流全部继承），仅入口不同（表单提交 vs LLM 函数调用）。
- 插件 description 同时作为 LLM 的工具选择依据，向导中提示管理员"描述写给 AI 看，说明什么场景该调这个接口"。

**Phase 2 —— 接口定义自动化获取（信息化系统主力路径）**：
- `openapi_import`：管理员提供 Swagger/OpenAPI 文档 URL 或 JSON，平台解析 paths/parameters/schema 自动生成 Manifest 草稿，管理员勾选要暴露的接口——实现"只填地址"的接入体验。
- `llm_assist`：管理员仅提供接口文档片段/自然语言介绍 + 示例请求响应，平台调 LLM 推断生成 Manifest 草稿，管理员确认修正后提交。
- 插件级 ACL（哪些角色可见可用）、`identity_header` 用户身份透传。

**Phase 3**：OAuth 鉴权、MCP 插件直连、多插件编排、插件市场/跨组织共享。
