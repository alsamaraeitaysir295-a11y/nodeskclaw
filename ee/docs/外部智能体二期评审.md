## 3. 设计缺口（spec 没明说但实施时会撞）

### 🔴 P1（开工前必须对齐，必须需求方明示）

| # | 缺口 | 原因 |
|---|---|---|
| P1-1 | **`output_hint` 在新表 function 上的存储位置**：spec §5 把 `invoke_config` 列为 function 列，**但 `output_hint` 没有独立列**——延续 Phase 1 实践（Phase 1 把 `output_hint` 嵌进 `invoke_config._output_hint` 子键）。是否沿用？还是给 function 表单独立列？ | spec §5 仅声明 `invoke_config`/`input_schema` 两列，未提 `output_hint`。为减少模型列数 + 复用 Phase 1 解析逻辑（`_output_hint` 在 `tool_service.py:239` 已读取），**默认沿用子键方案**。但 spec 应明示这一点。 |

## 7. 总体结论

**可放行**——无 P0 / P1 阻断。开工前**需需求方明示 2 项决策**：

1. **P1-1**：`output_hint` 在 function 表的存储方式（沿用 `invoke_config._output_hint` 子键 vs 独立列）
2. **P1-2**：function 表是否加 `(agent_id, sort_order)` 唯一约束，或硬约定 sort_order=0 仅给迁移默认 function

**P2 项**可在实施过程中由子代理自行决定，记录在 PR 描述里即可，不阻塞开始。

**建议的开工顺序**（按 spec §12 依赖图保持一致）：
- Task 0（description/default 补齐，半天）+ Task 1（新表 + 迁移 + 数据搬迁）并行 → 验证 alembic 跑通
- Task 5（OpenAPI 解析器 + 单测）单测为主，可独立并行
- Task 2（function CRUD API）+ Task 3（function invoke + 旧端点兼容）→ 必须先于 Task 4 / Task 6 / Task 7
- Task 4（前端功能选择器 + description/default UI）+ Task 7（前端向导导入流程）+ Task 8（i18n）并行
- Task 6（import API 端到端）+ Task 9（集成测试）+ Task 10（验收自测）

**Task 6/8 暂不动**（不在本批评估范围）。如需后续 OPUS 审查子代理输出，建议优先级：

- **P0**：无

- **P2**：其余 6 项在子代理 prompt 里要求"如有歧义按上述建议处理并在 PR 描述里注明"
