### 2.1 需求方的原始目标（原话浓缩，方案设计的出发点）

需求方（平台产品负责人）对"外部智能体插件化"的完整设想：

> 他们在系统封装好一个接口，接口里有他们想要接入的系统的 API 信息（api 接口、输入字段、输出字段、**这个字段的作用**），然后自动获取接口返回的信息处理，**变成单个智能体的所有功能**，这些功能有不同的输入输出以及对应的**是否可选**，然后根据所需的字段实现**自定义前端界面的展示**，比如需要上传文件，就留有一个上传文件的接口，**每个字段还要可以人为输入默认参数**。

## 1. 现状基线 → 本方案解决的两个结构性限制

Phase 1 的数据模型是 **1 插件 = 1 个 invoke 接口**（`invoke_config`/`input_schema` 是 agent 表上的单对象列）。信息化系统（MES/MOM/ERP）动辄几十个 API：

- 限制一：只能"一个 API 建一个插件"，无法形成需求方要的"单个智能体的所有功能"。
- 限制二：字段全靠管理员在向导里逐个手填，而这些系统基本都有 OpenAPI/Swagger 文档——字段定义（名称/类型/必填/**描述**/**默认值**）文档里现成的，应自动导入。

## 3. 总体设计

```
管理员贴 OpenAPI 文档 URL（或直接贴 JSON）
   ↓  POST /external-agents/plugins/import/openapi/preview（SSRF 闸门 + 5MB 限制）
解析器（纯函数）：paths → operations → 每个 API 一份 function 草稿
   入参自动映射：名称 / 类型 / required / description(字段作用) / default(默认值) / enum→select / format=date→date
   ↓  前端展示解析结果，管理员勾选要暴露的 API + 统一配置鉴权
确认导入：创建插件（status=draft）+ 批量创建 functions
   ↓  逐 function 试调通过 → active
用户端：进入智能体 → 功能列表 → 选中 function → 动态表单
   （字段作用提示 + 默认值预填 + 文件上传控件）
   ↓  POST /external-agents/{agent_id}/functions/{function_id}/invoke
tool_service 复用 Phase 1 全链路（校验/auth/SSRF/审计/结果处理）
```

数据模型核心变更：**新表 `external_agent_functions`，1 插件 N 功能**。

## 5. 数据模型变更：新表 `external_agent_functions`

新文件 `app/models/external_agent_function.py`：

```python
class ExternalAgentFunction(BaseModel):
    __tablename__ = "external_agent_functions"

    agent_id: Mapped[str] = mapped_column(
        String(36), ForeignKey("external_agents.id", ondelete="CASCADE"), nullable=False, index=True
    )
    name: Mapped[str] = mapped_column(String(128), nullable=False)        # 功能名（英文标识，如 query_orders）
    summary: Mapped[str | None] = mapped_column(Text, nullable=True)      # 功能说明（给用户和 AI 看）
    invoke_config: Mapped[dict | None] = mapped_column(JSONB, nullable=True)  # 结构同 agent.invoke_config（endpoint/method/auth/timeout/pass_mode/_output_hint）
    input_schema: Mapped[dict | None] = mapped_column(JSONB, nullable=True)  # 结构同 agent.input_schema（order+fields）
    status: Mapped[str] = mapped_column(String(16), nullable=False, default="draft", server_default="draft")  # draft|active|disabled
    sort_order: Mapped[int] = mapped_column(Integer, nullable=False, default=0, server_default="0")
    source: Mapped[str] = mapped_column(String(16), nullable=False, default="manual", server_default="manual")  # manual|openapi_import
    origin_meta: Mapped[dict | None] = mapped_column(JSONB, nullable=True)   # openapi 原始引用：{path, method, operationId, spec_version}
    version: Mapped[int] = mapped_column(Integer, nullable=False, default=1, server_default="1")
```

要点：
- `invoke_config`/`input_schema` **结构与 Phase 1 完全一致**（复用 ManifestInvokeConfig/ManifestInputSchema 校验），tool_service 无需感知存储位置变化
- 唯一约束：`(agent_id, name)` 联合唯一（同插件内功能名不重复）
- alembic 迁移放 `nodeskclaw-backend/alembic/versions/`，命名沿用目录内现有惯例

**存量兼容迁移（同一迁移文件内做数据搬迁）**：所有 `type='tool'` 且 `invoke_config IS NOT NULL` 的存量插件，各生成一条 function 记录（name='default'，summary=插件 description，source='manual'，status 继承插件 status），并回填 sort_order=0。**agent 表的旧列保留不删**（deprecated 注释标记），读路径全部走 functions 表，旧列仅作回滚保险。

## 6. OpenAPI 解析器设计

新文件 `app/services/openapi_import_service.py`，**纯函数无 IO**（拉取 doc 在 API 层做，解析器只吃 dict），便于单测。

### 6.1 支持范围

- OpenAPI 3.0 / 3.1（parameters + requestBody）
- Swagger 2.0（parameters 含 `in: body` 的 schema 引用）——两者参数模型不同，解析器内部归一化
- `$ref` 解析：仅支持文档内 `#/components/schemas/`（3.x）与 `#/definitions/`（2.0）引用，**拒绝跨文档 URL 引用**（安全）

### 6.2 类型与控件映射表（核心规则）

| OpenAPI 定义 | Manifest type | ui 控件 | 附加映射 |
|---|---|---|---|
| `type: string`（无 enum） | string | input | — |
| `type: string` + `enum: [..]` | string | **select** | options=enum |
| `type: string` + `format: date` | string | **date** | — |
| `type: string` + `format: date-time` | string | input | description 追加"ISO-8601 时间" |
| `type: string` + `format: binary` | **file** | **upload** | accept 不预设，管理员可改 |
| `type: integer / number` | number | number | — |
| `type: boolean` | boolean | switch | — |
| `type: array / object` | object | textarea | description 注明"JSON 输入" |
| parameter 级 `required: true` | required=true | — | — |
| parameter 级 `description` | **description**（字段作用） | — | 需求方核心诉求，自动带出 |
| schema 级 `default` | **default**（默认参数） | — | 需求方核心诉求，自动带出 |
| `example`（无 default 时） | 不映射 | — | 写入 description 括号补充，如"(示例: 热压1线)" |
| path 参数（`in: path`） | 正常字段 | — | endpoint 模板中的 `{param}` 保留，调用时做 URL 替换 |

### 6.3 每个_operation → function 草稿_

- `name`：优先 `operationId`（清洗为合法标识符），否则 `{method}_{path 清洗}`
- `summary`：operation 的 summary/description
- `invoke_config`：endpoint=服务器基址（servers/basePath 解析）+ path；method；auth 由管理员统一配置（不从文档猜）
- `input_schema`：按 §6.2 映射 parameters + requestBody 的 flattened 字段（嵌套对象拍平到一层，字段名用点号路径如 `address.city`）
- `output_hint` 建议：响应 200 schema 为 array → `display=table, items_path=''`；object 含数组字段 → `table, items_path=该字段名`；否则 `json`。**标记为建议值，管理员在预览界面可改**

### 6.4 解析器不做的事

- 不发任何网络请求（预览/导入的 doc 拉取在 API 层，走 SSRF 闸门）
- 不猜测鉴权（文档的 securitySchemes 仅作提示展示，由管理员选择 bearer/api_key_header 并填 token）
- 不自动激活（导入的 function 一律 draft，试调通过才 active）

## 7. 后端 API 变更

全部加在 `app/api/external_agents.py`（沿用现有 `require_org_member_role("operator")` 权限模式，invoke 用户态放行同 Phase 1）。

### 7.1 OpenAPI 导入（新增）

```
POST /external-agents/plugins/import/openapi/preview
  请求体：{ "doc_url": "http://..." } 或 { "doc": {...} }，二选一
  行为：doc_url 过 SSRF 闸门 + 拉取（5MB 上限，超限 413；非 JSON 422）→ 解析器 → 返回草稿列表
  响应：{ "spec_version": "3.0.1", "servers": [...], "functions": [
      { "name", "summary", "method", "path", "fields": [{name,type,ui,required,description,default,options}...],
        "output_hint_suggestion": {...}, "warnings": [...] } ] }
  不落库。

POST /external-agents/plugins/import/openapi
  请求体：{ "name", "description", "icon_emoji", "doc_url"?, "doc"?,
            "auth": {type, header_name?, token},
            "selected": [ { "name", "summary"?, "method", "path",
                            "output_hint"?, "field_overrides"? : {字段名: {default?, description?, ui?}}} ] }
  行为：重新拉取并解析（以服务端为准，不信任前端回传的完整草稿）→ 按 selected 的 method+path 匹配 →
        创建插件（type=tool, status=draft, invoke_config.auth 为统一鉴权）+ 批量创建 functions（source=openapi_import, origin_meta 记录 path/method）
  响应：创建的 agent + functions 列表
```

安全：doc_url 与 invoke endpoint 同样过 `resolve_endpoint_for_request`（org allow-list）；拉取超时 15s；文档大小 >5MB 拒绝；解析出的 endpoint 域必须与 doc 的 servers 域一致（防文档内路径注入到任意主机）。

### 7.2 function CRUD（新增）

```
GET    /external-agents/{agent_id}/functions                      列表（含 status/sort_order）
POST   /external-agents/{agent_id}/functions                      手动加功能（body 走 PluginManifest 的 tool 分支校验）
PATCH  /external-agents/{agent_id}/functions/{function_id}        编辑（name/summary/invoke_config/input_schema/status/sort_order；变更后 version+1）
DELETE /external-agents/{agent_id}/functions/{function_id}        删除
POST   /external-agents/{agent_id}/functions/{function_id}/probe  单功能试调（复用现有 probe 逻辑，读 function.invoke_config）
```

归属校验：所有 function 端点必须先校验 `agent.org_id == 当前 org`（复用现有 `_get_agent_or_404` 模式），**不允许出现 Phase 1 那种只按子资源 id 过滤的 IDOR**。

### 7.3 function 级调用与上传（新增）

```
GET   /external-agents/{agent_id}/functions/{function_id}/form      返回该 function 的 input_schema（含 description/default）+ 脱敏 invoke_config
POST  /external-agents/{agent_id}/functions/{function_id}/invoke    复用 invoke_tool，参数来源改为 function.input_schema/invoke_config
POST  /external-agents/{agent_id}/functions/{function_id}/files     复用 upload_plugin_file，白名单/max_mb 读 function 的 file 字段
```

### 7.4 旧端点兼容（保留一个版本）

`/{agent_id}/invoke`、`/{agent_id}/files`、`/{agent_id}/form` 保留：内部代理到"该插件 sort_order 最小的 active function"。存量前端与 API 消费方不破坏；响应头加 `Deprecation`。下一版本再移除。

## 9. 安全清单（本方案新增项）

1. doc_url SSRF：过 `resolve_endpoint_for_request` + org allowed_cidrs，与 invoke 同标准
2. 解析出的 endpoint 域校验：必须落在 doc servers 声明的域内（防恶意文档把 invoke 指到内网其他主机）
3. 拒绝跨文档 `$ref`（URL 形式的 ref 直接报 warning 并跳过该字段）
4. 文档大小 5MB 上限、拉取超时 15s
5. 导入确认以服务端重新解析为准，**不信任前端回传的草稿内容**（防篡改 endpoint 注入）
6. token 落库 encrypt_sensitive；preview 响应不含任何密钥
7. function 归属校验：org 隔离 + （用户态调用时）沿用 Phase 1 会话/权限模型

## 13. 验收标准

1. 贴一个 Swagger URL → preview 返回全部 operation 草稿，字段含名称/类型/required/**description**/**default**（enum 转 select、format=date 转 date 控件）
2. 勾选 3 个 operation 导入 → 生成 1 个插件 + 3 个 functions（status=draft）
3. 用户端进入该插件 → 功能列表可见 → 每个功能独立表单（含 upload 控件）→ invoke 成功且结果按 output_hint 渲染
4. 字段说明显示在字段下方；默认值预填且用户可覆盖；API 直调缺省字段时服务端注入 default
5. **存量单功能插件迁移后功能正常**（旧 /invoke 兼容代理回归通过）
6. doc_url 指向 allow-list 之外的内网地址 → 拒绝；>5MB 文档 → 413；跨文档 $ref → warning 跳过
7. Swagger 2.0 与 OpenAPI 3.x 双格式解析测试全绿（测试矩阵覆盖 enum/format/binary/default/$ref）
8. 双用户隔离：A 组织看不到 B 组织插件的 functions（org 归属校验）
9. 所有新文案 zh-CN/en-US 双语齐全；密钥在任何响应/日志无明文
