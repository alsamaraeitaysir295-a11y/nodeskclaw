# DeskClaw 启动指南（WSL2 + Docker Compose 环境）

> ⚠️ **本文档已过时（2026-08-26 起停用）**：所述端口（80/4510）、部署目录、启动方式均已变更，
> 按本文操作会撞端口占用（Windows svchost 占 80/4510）。
> 现行方案与踩坑记录见 [DeskClaw-WSL2部署问题与解决方案.md](DeskClaw-WSL2部署问题与解决方案.md)。

> 适用场景：Windows 11 + WSL2（Ubuntu），Docker 跑在 WSL 内（非 Docker Desktop），
> 全部服务（backend / portal / llm-proxy / postgres / AI 员工）以容器方式运行，
> 由仓库根目录的 `docker-compose.yml` 统一编排。
>
> 仓库路径以 `E:\claude_workspace\nodeskclaw` 为例，WSL 内对应
> `/mnt/e/claude_workspace/nodeskclaw`，按实际路径替换。

## 0. 架构总览

```
Windows 登录
  ↓ 自动（Startup 目录的保活脚本）
WSL 常驻运行（deskclaw-wsl-keepalive.vbs）
  ↓ 自动（WSL 内 systemd）
Docker daemon 启动
  ↓ 自动（所有容器 restart: unless-stopped）
┌─────────────────────────────────────────────┐
│ postgres(5432) → backend(4510) → portal(80) │
│ llm-proxy(4511)   fwd4100(转发器)   AI 员工×N │
└─────────────────────────────────────────────┘
```

| 容器 | 作用 | 宿主端口 |
|------|------|---------|
| nodeskclaw-postgres-1 | PostgreSQL 16 数据库（库名 nodeskclaw_rbac） | 未发布（仅容器网络） |
| nodeskclaw-nodeskclaw-backend-1 | FastAPI 后端 | 4510 → 8000 |
| nodeskclaw-portal-1 | Vue3 门户（nginx 静态托管 + /api 反代） | 80 |
| nodeskclaw-llm-proxy-1 | LLM Proxy | 4511 |
| fwd4100 | socat 转发器：容器 → Windows 宿主 4099 测试服务 | 仅容器网络（host 模式监听 4100） |
| ce-shi-* / qa-* / mu-ban-* / zhu-shou-* | AI 员工实例（Docker provider） | 13000+ |

**日常开机基本全自动**：登录后等 1-2 分钟，直接访问 http://localhost 即可。

## 1. 日常启动（通常无需手动操作）

开机登录后，启动链条自动完成：

1. `Startup\deskclaw-wsl-keepalive.vbs` 拉起 WSL（隐藏窗口 `sleep infinity` 常驻）
2. WSL 内 systemd 自动启动 Docker daemon
3. 所有容器 `restart: unless-stopped` 自动拉起

### 验证服务正常

```bash
# Windows 侧任意终端
curl http://localhost:4510/api/v1/health    # {"status":"ok"}
curl -o /dev/null -w '%{http_code}\n' http://localhost    # 200
```

### 访问地址

| 服务 | 本机 | 局域网（其他设备） |
|------|------|------------------|
| 门户 | http://localhost | http://10.50.54.201 |
| 后端 API | http://localhost:4510/api/v1 | http://10.50.54.201:4510/api/v1 |

> 局域网 IP 通过 `ipconfig` 查以太网适配器的 IPv4 地址；
> 防火墙已放行 80/4510 端口（之前已配置）。

## 2. 手动操作场景

所有操作先进 WSL：

```bash
wsl -d Ubuntu
```

### 2.1 万一容器没起来 / 全部停了

```bash
cd /mnt/e/claude_workspace/nodeskclaw
docker compose up -d          # 一键拉起全部
docker compose ps             # 查看状态
```

### 2.2 修改代码后重建部署

```bash
cd /mnt/e/claude_workspace/nodeskclaw

# 后端（Python 代码改动）
docker compose build nodeskclaw-backend
docker compose up -d nodeskclaw-backend

# 前端（Vue 代码改动）
docker compose build portal
docker compose up -d portal

# 两者都改了
docker compose build nodeskclaw-backend portal
docker compose up -d nodeskclaw-backend portal
```

> 镜像内已含 Alembic 迁移脚本，容器启动时自动执行 `alembic upgrade head`，
> 无需手动跑迁移。

### 2.3 查看日志

```bash
docker compose logs -f nodeskclaw-backend --tail 50    # 后端实时日志
docker compose logs -f portal --tail 20                # nginx 日志
docker logs <AI员工容器名> --tail 30                     # 单个 AI 员工
```

### 2.4 彻底停止 / 恢复

```bash
docker compose down          # 停止并移除容器（数据卷 pg_data 保留）
docker compose up -d         # 恢复
```

> **注意**：`docker compose down` 会停掉所有服务包括 AI 员工；
> WSL 本身由保活脚本持有，不会自动关闭。

## 3. 两个辅助设施（勿删）

### 3.1 WSL 保活脚本

位置：`C:\Users\<你>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\deskclaw-wsl-keepalive.vbs`

作用：登录时自动启动一个隐藏的 WSL 会话（`sleep infinity`），防止 WSL 在
最后一个会话关闭后约 8 秒自动关机（WSL 默认行为），导致所有容器失联。

- 删除后果：WSL 会随会话关闭自动关机，服务表现为"莫名失联"
- 手动拉起等价操作：`wsl -d Ubuntu -e bash -c "exec sleep infinity"`（后台）
- 彻底关闭 WSL：删除脚本后 `wsl --shutdown`

### 3.2 fwd4100 转发容器

作用：AI 员工/后端容器出站访问 Windows 宿主上的测试服务（端口 4099）。
WSL2 mirrored 网络下容器无法直接访问 Windows 原生进程，需经
host.docker.internal:4100 → WSL 回环 127.0.0.1:4099 → Windows 进程。

```bash
# 查看 / 重启 / 重建
docker ps --filter name=fwd4100
docker restart fwd4100

# 测试服务换了端口（如 4099 → 5099）：
docker rm -f fwd4100
docker run -d --name fwd4100 --restart unless-stopped --network host \
  alpine/socat TCP-LISTEN:4100,fork,reuseaddr TCP:127.0.0.1:5099
```

外部 Agent 的 OpenAPI 导入 URL 填 `http://host.docker.internal:4100/openapi.json`。

## 4. 环境配置（一次性，已配好）

### 根目录 `.env`

```env
# 数据库（容器网络内服务名）
DATABASE_URL=postgresql+asyncpg://nodeskclaw:nodeskclaw123@postgres:5432/nodeskclaw_rbac

# AI 员工回连后端地址（容器经 host.docker.internal 回连宿主映射端口）
AGENT_API_BASE_URL=http://host.docker.internal:4510/api/v1

# 部署环境标识：server = 同 docker 网络走服务名；留空 = 本地开发
# DEPLOY_ENV=server
```

> `AGENT_API_BASE_URL` 留空自动推导（本地 → host.docker.internal:4510；
> 服务器 → nodeskclaw-backend:8000），显式设置优先。

### SSRF 网段白名单（组织级）

外部 Agent 的目标服务在内网时，需将网段加入组织白名单，否则 SSRF 防护拦截：

```bash
docker exec nodeskclaw-postgres-1 psql -U nodeskclaw -d nodeskclaw_rbac \
  -c "UPDATE organizations SET external_agent_allowed_cidrs='[\"10.50.54.0/24\",\"10.50.55.0/24\"]'::jsonb WHERE deleted_at IS NULL;"
```

或通过门户：组织设置 → 外部 Agent 允许网段。

## 5. 服务器部署差异

本指南针对本地开发环境。部署到服务器（同一 docker 网络）时：

1. `.env` 加 `DEPLOY_ENV=server`（AGENT_API_BASE_URL 自动变为 `http://nodeskclaw-backend:8000/api/v1`）
2. 无需 fwd4100 转发器（服务器上无 Windows 宿主服务）
3. 无需 WSL 保活脚本
4. Windows 下必须显式设 `NODESKCLAW_DATA_DIR`（AI 员工数据目录，绝对路径）

## 6. 常见问题

### Q1: 开机后服务访问不通

等 1-2 分钟让容器自启完成；仍不通则进 WSL 手动 `docker compose up -d`。

### Q2: WSL 自动关机导致服务失联

检查 Startup 目录的保活脚本是否存在；被删则按 3.1 节重建。

### Q3: 后端容器反复重启

```bash
docker logs nodeskclaw-nodeskclaw-backend-1 --tail 30
```

常见原因：数据库未就绪（等 postgres healthy 后自动恢复）、Alembic 迁移冲突。

### Q4: AI 员工连不上后端

后端日志查 `host.docker.internal:4510` 是否可达；不可达则 WSL 或 Docker 网络异常，
`wsl --shutdown` 后重新拉起（保活脚本会自动重建）。

### Q5: 外部 Agent 导入 URL 填什么

指向 Windows 宿主上的服务用 `http://host.docker.internal:4100/openapi.json`
（经 fwd4100 转发）；直接填局域网 IP（如 10.50.54.233）时目标网段需在 SSRF 白名单内。
