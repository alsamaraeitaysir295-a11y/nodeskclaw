# 技能市场统计功能方案（v1，口径已终版确认）

> 日期：2026-08-27
> 状态：实现中
> 需求：统计哪些 skill 下载次数多、使用次数多，按 总计/月/周 维度做简单展示页

## 最终口径（2026-08-27 与用户确认）

- **两个榜单**：下载量榜、使用量榜（不做三榜）
- **下载量** = zip 下载到本地 + fork 下载到个人库 + 员工配置界面安装技能，**合并计数**（fork 到组织/公共也记录事件但不进下载榜，留作未来口径）
- **使用量** = **实际调用次数**，在 llm-proxy 解析模型发起的 tool_calls：
  - `read` 工具且 path 匹配 `.openclaw/skills/{skill_name}/SKILL.md` → 归因到该 skill（"skill 被实际打开"的最强信号）
  - MCP 工具名含 server 前缀 → 查 `InstanceMcpServer`（source='gene' 且有 source_gene_id）归因
  - 裸工具名（exec/read 普通文件等）无法归因，跳过
  - 局限：计"模型发起的调用"，工具执行失败也计；只覆盖走 proxy 的 LLM 流量（平台默认全走）
- **可见范围** = 组织内所有登录用户；数据范围 = 公共市场（visibility='public'）+ 本组织（org_id=当前组织）
- **历史数据**：事件表上线后开始积累，初期榜单为空（显示提示）

## 为什么是 llm-proxy 路线（调研结论 2026-08-27）

后端目前**完全看不到 skill 被真实调用**：gene 安装只是把 SKILL.md 写进实例文件系统，执行在 agent 运行时内部（system prompt 注入 + read 工具按需加载），channel/tunnel 协议里没有 tool 事件。候选路径：
- ~~security 层 WS~~：需修三处断线（空插件/fail-open/env 未注入）+ 实例换 -sec 镜像 + 验证上游 hook（openclaw#5943），工程量大
- **llm-proxy**：所有实例 LLM 请求必经，请求响应流里有完整 tool_calls；proxy 已有 `ctx.instance`（id/org/created_by）和直连同库写 `llm_usage_logs` 的先例——**只改 proxy 一个服务**，已选定

## 后端（nodeskclaw-backend）

### 1. 事件表 `gene_market_events`
- model `app/models/gene_market_event.py`：`GeneMarketEvent`
  - `gene_id`(FK)、`gene_slug`、`gene_name`（反范式冗余，gene 删除后榜单仍可显示）
  - `event_type`：`'fork' | 'zip_download' | 'skill_use'`
  - `target_scope`（fork 目标，可空）、`user_id`、`org_id`
  - BaseModel（id/created_at/updated_at/deleted_at 软删除）
  - 索引：`(gene_id, event_type, created_at)`、`(event_type, org_id, created_at)`
- Alembic `uv run alembic revision --autogenerate`，down_revision 应为 `6f131501f1cc`
- 部署注意：容器启动自动迁移；DuplicateTable 参照部署文档坑 5，勿删表

### 2. service `app/services/gene_market_stat_service.py`
- `record_event(...)`：非阻塞写入（try/except warning+rollback）
- `get_market_stats(org_id, dimension)`：cutoff（total=None / 本月 1 号 / 本周一 0 点，参考 `api/performance.py`）+ scope 过滤（public | org_id）
- 返回 `{ totals: {download, use}, rankings: { download: Top10, use: Top10 } }`，每项 `{gene_id, slug, name, count}`
- 下载榜 = fork(target_scope='personal') + zip_download 求和；使用榜 = skill_use 求和

### 3. API 与埋点
- `app/api/genes.py` 加 `GET /genes/market-stats?dimension=total|month|week`（`get_current_org` 依赖，非 admin 区）
- 三个下载类埋点：fork 端点（`record_event('fork', target_scope=...)`）、`download_gene`（zip）、`install_gene` 端点（员工配置界面安装，`record_event('install')`；注意 `install_gene_prerestart` 是实例重启时的幂等重装，**不埋**，否则每次重启都会虚增计数）

## llm-proxy（nodeskclaw-llm-proxy）

### 4. 新模块 `app/skill_usage.py`
- `ToolCallCollector`：流式按 index 累积 `delta.tool_calls` 片段，非流式直接取 `message.tool_calls`，按 tool_call id 去重
- 归因（一次响应只查 2 条 SQL）：
  - 该实例已装基因清单（InstanceGene status='installed' JOIN Gene，skill_name = manifest.skill.name ?? slug）
  - 该实例 InstanceMcpServer（source='gene' 带 source_gene_id）
  - Python 侧匹配：read+SKILL.md 路径正则 / 工具名含 server 名
- 命中后批量 INSERT `gene_market_events`（event_type='skill_use'，user_id=instance.created_by, org_id=instance.org_id），`asyncio.create_task` 非阻塞，失败仅 warning

### 5. proxy.py 挂三个钩子
- `_handle_non_stream`（resp_body 解析后）

- 探测请求（is_probe）跳过

## 实施中确认的两个关键决策/坑（2026-08-27）

1. **AI 员工默认放开 `read` 工具**（用户拍板）：实例 `tools.allow` 原本只有 10 个
   `nodeskclaw_*` 协作工具，`read` 被剥掉导致技能只剩 system prompt 摘要层（模型
   读不了 SKILL.md）。已在 `llm_config_service.py` 加 `DEFAULT_BUILTIN_TOOL_ALLOW = ("read",)`
   并入三处 tools.allow 生成逻辑；**存量实例**需手工补（往
   `/root/.openclaw/openclaw.json` 的 `tools.allow` 追加 "read"）+ 重启容器。
   `exec`/`write` 仍锁定。
2. **流式 tool_calls 分片拼装的坑**（minimax 实测）：首分片带 `id + index`，续分片
   **只带 index 不带 id**——collector 的 key 必须以 index 优先（id 仅首片出现），
   否则参数碎片分裂到不同条目、arguments 拼不完整。见 `skill_usage.py`
   ToolCallCollector 的 key 规则注释。
